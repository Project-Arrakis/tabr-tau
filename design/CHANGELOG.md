# Changelog of the design module

Tags of this module are `design/vX.Y.Z`. The module is version 0.x: until v1.0.0 a name can change in a minor version, and the entry says so. Patch: a value changes and no name does. Minor: a token, a component or a file is added (or a name changes before v1). Major: a rename or a removal after v1. A tag is never moved; a bad tag is answered by a new tag and a `retract` line in `go.mod`.

Each tag needs an entry here whose heading is `## vX.Y.Z` followed by the date: the release workflow uses the entry as the release notes and fails without it.

## v0.3.0 (2026-11-11)

Palettes: eighteen sets of colours that recolour a look.

- **Eighteen palettes in one new file, `assets/palettes.css`.** A palette is chosen with `html[data-palette="ID"]` and changes colour tokens only (the names the looks already define, plus `accent-color` and `scrollbar-color`): no type, space, shape, motion, texture or component, so a layout never moves. It applies in its own theme: sixteen palettes in the dark theme and two, Fremen Sietch and Mentat, in Dayside (the light theme); in the other theme a palette is simply not in effect. Its selectors are more specific than the looks', so the order of the stylesheets does not matter, and removing the attribute gives the look's own colours back. Arrakis Incandescent is first.
- **Ids describe the colours** (`warm-charcoal`, `sand-linen`, `paper-grey`, `deep-teal` and so on); the franchise names are the labels only, in `design.Palettes`.
- **Values.** The colours of each palette are those of the fan-made editor themes under the MIT Licence that NOTICE already names (alpha removed). A colour is moved toward white (dark palettes) or toward black (Dayside palettes) only where a check needs it, in steps of 4 %, and the comment of each palette in the file names the colours it moved. The checks: text and quiet text 5.1:1 on the four surfaces and 4.6:1 on every tint a component draws; the accent, gold, sky, ok, warn and bad colours 4.6:1; the boundary of a control and the focus ring 3:1; the fill of a primary button and of a switch that is on, with a label that holds on it, also when hovered. `--k-boost` (a token the looks already define) is raised by a palette as far as the text on the stronger accent tints allows. The file is generated from a table and these rules (`palettes_gen_test.go`; `go test -run TestPalettesCSSIsGenerated -update-palettes` writes it) and a test fails when the committed file differs.
- **Go API.** `design.PalettesFile`, `design.Palette` (`ID`, `Name`, `Group`, `Theme`), `design.Palettes()` (the order to show them, grouped), `design.PaletteFiles(id)` (the stylesheet to link after the look's files; none for `design.NoPalette`; a refusal for any other string, like `LookFiles`), `design.ThemeDark`, `design.ThemeLight` and `design.NoPalette`. `design.Version` is v0.3.0.
- **Kitchen sink.** A Colours list (the look's own colours, then the palettes by group) on the first panel.
- **Tests.** The contrast tests of 0.2.0 (every text, line and focus token on the four surfaces, and the tints, hover mixes and fills the components compute) now run for each of the eighteen palettes on each of the three looks, with the palette's tint strength; and new tests of the stylesheet's structure (two blocks per palette with the same values, only the names a palette may set), of its specificity over the looks, and of the list against the stylesheet and the kitchen sink.
- **Nothing else changes.** Every other file of 0.2.0 is as it was.

## v0.2.0 (2026-11-09)

The Look: three looks with their components, the icons, the heading typeface, the Motion setting and the checks. Refs #572, #573, #574.

- **Three looks, each in a dark theme (the default) and a light one, Dayside.** New files `assets/tokens-fremen.css` (the default look, a stillsuit grey-brown with a cobalt accent), `assets/tokens-awakening.css` (near-black with spice-orange light and bronze rules) and `assets/tokens-sietch.css` (the look the 0.1.0 tokens started from). A look is chosen by linking its files in this order: `tokens-LOOK.css`, `components-LOOK.css`, `components.css`, `motion.css`. `design.Looks()`, `design.DefaultLook` and `design.LookFiles(look)` give the ids and the file names, so a program that lets its user switch never builds a file name from a stored string.
- **`assets/tokens.css` is unchanged**, byte for byte, and keeps the values of 0.1.0. Every name of 0.1.0 is also defined in each look's file (`--t-base` and `--r-4` as aliases), so a program can move to a look by changing the link. New names in the looks: `--c-sunken`, `--c-gold`, `--c-bronze`, `--c-hair`, `--c-focus`, `--c-glow`, `--c-on-spice`, `--c-switch`, `--c-on-switch`, `--c-scrim`, `--c-dust-1` to `-3`, the map colours `--m-*`, the sizes `--t-2xl`, `--hit`, `--hit-dense`, the shadows `--e-3`, the textures `--grain`, `--weave`, `--vignette`, and the motion tokens `--mo-ease`, `--mo-fill`, `--mo-flash`, `--mo-water`, `--mo-attn`, `--mo-ping-once`, `--mo-delay`, `--mo-breathe`, `--mo-spin`, `--mo-shimmer`, `--mo-low` and others.
- **Components** (`d-` classes) in `assets/components-LOOK.css`: the app bar and nav, status pill, scope chip, panel and folding head, buttons, switch, list row, badge, segmented control and tabs, certainty chip, fields, meter, tooltip, popover, hover card, banner, alert, toast, modal, empty state, key/value list, table, sparkline, disclosure, loading skeleton. `assets/components.css` holds what the looks share: the tile (`d-tile`), the rail and its drawer (`d-rail`, `d-edge`, under 760 px wide it lies over the page), the type specimen (`d-display`), larger touch targets, reachable tooltips, a more-contrast rule and the forced-colours block. `kitchen-sink/index.html` shows every class (not embedded in the Go package).
- **Icons.** `assets/icons.svg`, a sprite of 53 icons drawn for this module (24 px grid, one colour), including the outlines of the drop, the can and the shield of the toast icons. `<svg class="d-i"><use href="/design/icons.svg#i-drop"/></svg>`. Whether the sprite loads from a file under `default-src 'none'; img-src 'self'` in the apps' window is not yet checked there; a program that cannot use it builds the same symbols from a script.
- **Typeface.** Dune Rise (SIL Open Font License 1.1), used unmodified, for headings and caps labels only (`--t-heading`; never body text, numbers, buttons or names); the licence text, `SHA256SUMS` and a test that the embedded bytes equal it are in `assets/fonts/`. `html[data-heading-font="system"]` turns it off. **The font file itself is added by the commit that prepares the tag** (see PROVENANCE.md); the release workflow refuses a tag without it. A program that serves `fonts/` needs `font-src 'self'` in its content security policy.
- **Motion.** `assets/motion.css` and the setting `html[data-motion]` (`full`, `calm`, `off`); the system setting `prefers-reduced-motion` makes Calm the default unless the person has chosen (`html[data-motion-src="user"]`); `html[data-doc-hidden]` pauses what runs. An app marks its own loops with `data-loop`. Every loop is 333 ms or slower and has a rule that stops it in Calm, in Off and under the system setting.
- **Grain.** The Awakening look's texture is the tiled picture `assets/grain.svg`, never a `data:` URL. The Fremen look draws its cloth with CSS only.
- **Focus.** A cut (chamfered) part of the Awakening look drops its clip-path whenever it, or something inside it, shows the focus ring, so the ring is never cut. The Fremen and Sietch looks have no clip-path.
- **Forced colours.** A `@media (forced-colors: active)` block gives every gradient-drawn or shadow-drawn part a real border and every state a border, text or mark of its own; `prefers-contrast: more` removes the textures and raises the dividers. Print is not supported.
- **Values changed from the draft, to pass the checks:** the hover tint of a Sietch alert (20 % to 16 %), the hover of the Sietch primary button (88 % to 94 % white), the flash of a changed row (30 % to 22 %), the small counts and the certainty ring no longer use `opacity`, the scope chip, the critical-meter mark and the badge sizes are 11 px or `min-height`, and a range input is 24 px high.
- **Go API.** `design.Handler` sends an explicit type for every extension the module carries (`.css`, `.svg`, `.ttf`, `.txt`, and `SHA256SUMS` as text) and `application/octet-stream` for any other; `design.Version` is v0.2.0; new `Looks`, `DefaultLook`, `LookFiles`, `IconsFile`, `GrainFile`, `FontFile`, `FontLicence`.
- **Tests.** Contrast of every text, line and focus token on the four surfaces for each look and theme, and of the tints, hover mixes and fills that the components compute; the names of 0.1.0 in every look; no `data:` URL, no outside address, every `url()` a file of the module; no inline style, script or event attribute in the kitchen sink and no HTML built from a string in any script; every selector with a clip-path named by a focus rule of higher specificity; every loop slow enough and stopped by the Motion setting; sizes (no text under 11 px, no target under 24 px, 44 px for touch); the forced-colours block and its states; the heading face on headings only; every class of the components used in the kitchen sink; the font checksum and licence; the explicit file types; notices and provenance; no private context and no image file but the module's own SVG.
- **Notices.** `NOTICE` and the repository's third-party notices carry the Dune Rise copyright line and licence and the MIT notice of the palette source (Copyright (c) 2025 FedaykinDev).

## v0.1.0 (2026-11-08)

First version: the design tokens only. Refs #553.

- New file `assets/tokens.css`: CSS custom properties for colour (`--c-ground`, `--c-panel`, `--c-raised`, `--c-rule`, `--c-text`, `--c-dim`, `--c-spice`, `--c-sky`, `--c-ok`, `--c-warn`, `--c-bad`), type (`--t-body`, the sizes `--t-xs` to `--t-xl`), spacing (`--s-1` to `--s-6`, a 4 px grid), shape (`--r-1` to `--r-4`, `--r-pill`), elevation (`--e-1`, `--e-2`) and motion (`--mo-fast`, `--mo-base`, `--mo-slow`). The dark theme is the default; the light theme follows the system setting, or is forced with `data-theme="light"` (and the dark one with `data-theme="dark"`).
- The values are the ones the first program that adopts the module already shows, so adopting it changes nothing on screen. Nothing else is in this version: no components, icons or word list.
- Go API: `design.Assets` (the embedded files, rooted at the assets folder), `design.Tokens()` (the stylesheet), `design.Handler()` (a read-only handler for the files; a stylesheet is always `text/css`), `design.TokensFile` and `design.Version`.
- Tests: the module imports the standard library only; the stylesheet's text colours are 4.5:1 and its control boundary 3:1 on the three surfaces in both themes; the two light blocks are the same; every name has a prefix; the version, the `VERSION` file and this file agree.
