# Layer 1 (design) audit: consolidated findings register

Date: 2026-09-30. Subject: `docs/design/2026-09-30-architecture-and-implementation-plan.md` v0.1.
Method (Requirement 20): eight independent, read-only hat reviews (Architect, Security Architect, GRC,
Network, Cloud Security, UI/UX, DBA, QA/Test), each told to verify claims against real files and data and to
map findings to STRIDE. 71 raw findings were merged into 21 items below. Consolidator spot-checked four
high-impact claims against the code before accepting them (all confirmed: `GET /` is exempt from the token
check `server.go:50`; unescaped `${r.stack_size}` attribute interpolation `index.html:111`; `query_only`
toggled on the shared connection `save.go:263`; non-empty child inventory left dangling `ops.go:366`).

Nothing had been fixed in code when this audit was written; the status column below is as of 2026-09-30 and the progress log at the end records what has landed since. Status "PLAN" = design updated in v0.2 with a scheduled task.
Status "OPERATOR" = needs a decision or action from the operator. GitHub issues are **not yet filed**
(outward-facing on a public repo; awaiting operator go-ahead), so this file is the interim register.

## Severity adjustments made by the consolidator
- UX-1 (no review-before-save pane): hat said CRITICAL, consolidated **HIGH**. It is a design gap in a feature
  that is planned, not a shipped defect; the hazard it describes (unreviewed Save) exists today and is covered
  by F-06.
- QA-1 kept **CRITICAL**: it gates every later feature (a green suite that cannot detect a wrong write).
- CLOUD-1 kept **CRITICAL**: live credential exposure that exists now and needs operator action.
- No hat contradicted another on a fact. The DBA hat reported no outright false doc claim; the Architect, QA,
  Network and Security hats each found false ones, because their scopes differ. All false claims are listed in
  F-15 and corrected in plan v0.2.
