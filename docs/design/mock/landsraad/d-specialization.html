Example data. The character's levels, the tier meters and the states are made up for this picture. The house to specialization link and the regions are the community tracker's (see specialization-research.md). Nothing here reads a save.

This page is not the accessible build. It switches between 18 prebuilt views with CSS only, so each view reads in the order it shows, but it cannot keep focus on the control you used, set aria-sort, or announce the change. The editor re-renders the list in the displayed order with script, one section and a real heading per group, and never reorders with CSS order (decision D15 in the research page). The controls need a browser with :has() (Chrome 105, Safari 15.4, Firefox 121 or newer); without it the page shows the default view and the controls do nothing.

About this mock-up
  • The sort follows mock-up A: a heading is a sort, click for ascending, click again for descending (Specialization and Level are two more headings; the board's other headings are not redrawn). There is one Group by control, None, Region or Specialization. Reset view returns to House, ascending, no grouping.
  • With Group by Specialization the sort orders the groups, and inside a group the houses are A to Z, since the five houses of a line share one level. With Group by Region the four regions keep one fixed order (as in mock-up A) and the sort orders the houses inside each. The line above the list says both parts.
  • The icon is a small original glyph drawn for this page, always with the line's name beside it. The final glyphs go through the design review, and the research page recommends original glyphs, not the game's art.
  • House names are the save's (Mikkarol, Spinette), which the board already shows.
  • Whether the chosen view is remembered between visits is decision D18; this page does not remember it.
