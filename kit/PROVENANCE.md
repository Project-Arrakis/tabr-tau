# Where the contents of this module come from

Every file in this module is listed here with where it comes from. The rule for what may enter the module:

- code written for this project, and tables of the game's identifiers and numbers that come from a public source or from the installed game's own content files read without modifying them;
- a data file of an MIT-licensed project, copied unchanged, with that project's copyright and licence text in [NOTICE](NOTICE) (one so far: `gamedata/regions/hagga-regions.json`);
- nothing else: no game artwork, no text or names copied from the game's art or audio, no save, log or snapshot of a person's machine, and no code from another project.

Test data in this module is made by the tests (random bytes after the SQLite header, and containers built in the test), never read from a real save.

## gamedata/vehicles/vehicles.json (#401, moved in #555)

`gamedata/vehicles/vehicles.json` contains only the game's identifiers and numbers (no names, text, images or code of the game). The editor's names for the classes are its own words. It is read by
`vehicles.go` (the catalog) and `internal/ops/vehicle_spawn.go` (the write) and nothing else. Tank and Treadwheel are in the tables but in no save, and are not in the file.

**Game build.** Build `1.5.15.0` (Steam build `26083551`), read on 2026-10-27; the file records the build and the day (`build`, `read`). A hotfix changes tables: the file has to be made again from the tables of the new build (below), and a save that holds a module id the file does not know is refused, not guessed at.

**How vehicles.json is made.** `tools/vehiclegen` (`go run ./tools/vehiclegen -modules ... -build ... -read ... -out kit/gamedata/vehicles/vehicles.json`; its comment lists the inputs). It reads JSON dumps of the
four tables above, in the shape any table dump has (a one-element array with a `Rows` object), and the decoded module lists of the templates (`{"<Row>__slots": {"<Template>": [["<slot>", "<module id>"], ...]}}`). Making
those dumps takes a reader of the game's container files, which this repository does not contain, and the dump of the module lists takes reading the raw package; the tool only turns the dumps into the file and
refuses a result that is not consistent (`vehicles.Check`: every template names existing modules of its class, each in the slot of the module row, every mandatory slot filled, the tier equal to the chassis's grade).
Rules the tool applies: a module is offered when its id ends in a grade from 0 to 6 (grades 7 to 9 are rows of the table that belong to no template and appear in no save; a row with no grade is a faction's own module), placeholder rows
(`Polarcap`) are left out, and a module's slot is the module row's own slot type (a save keeps only the module id). The one vehicle that is a single module (the container vehicle) has no decoded list; its template is the one row of its model.
The shape of the rows of a class (the permission name, the component holds and their hashes, the properties the game writes only for that class) is not in the tables: it was read from saves the game wrote, and it is a table in the tool.

**How it was checked.** The module rows reproduce the numbers that vehicles of several classes saved (health, critical health, a full tank, the cargo hold: `gamedata/vehicles/vehicles_test.go`), every module id found in the saves studied is in the file, the template `T5_Inventory` of the medium ornithopter has exactly the modules of a real vehicle, and the templates `T0` of the Sandbike and the Buggy have exactly the modules of the vehicles the world places (most vehicles of a played save are exactly a template). That a vehicle built from these tables loads in the game is **not** yet checked.

**The chassis tanks.** The 24 Chassis rows carry the fuel capacity of the chassis (`fuel`): 23 rows have one (six vehicles, grades 0 to 6; the Container vehicle has none). `ChassisFuel` and `ChassisTanks` only read those rows. The tanks were read from `CDT_BaseVehicleModules`, field `m_StaticData.m_FuelCapacity` of the Chassis rows (issues #467 and #469, `docs/design/2026-10-28-vehicle-fuel-tanks.md`).
